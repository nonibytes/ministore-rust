# Repository instructions

## Documentation

- Write documentation as a self-contained description of the repository's
  current behavior. A reader must not need commit history, a pull request, or a
  prior conversation to understand it.
- Do not describe product documentation in terms of an earlier implementation
  or editing event. Avoid framing such as "previously," "now," "no longer,"
  "changed," "improved," "this run," or "the old behavior."
- State behavior, constraints, benchmark conditions, and results directly. Git
  history is the record of how the repository changed.
- Remove superseded guidance instead of retaining historical comparisons in
  current-state documentation.
- Changelogs, release notes, migration guides, and explicitly labeled roadmaps
  may discuss time or transitions because that is their purpose. Keep that
  framing inside those document types.
